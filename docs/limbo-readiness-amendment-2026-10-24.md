# Receipt-path readiness clarification - 24 October 2026

Official benchmark collection has not started. The measured policy, native
environment, selection rule, four arms, limits, native grader and all-planned
analysis remain unchanged.

The excluded guarded `migration_log` execution at index 0, under `timeout_post`,
returned normally and passed full independent native replay. The fault
triggered. It made three model dispatches, requested the disabled simulated
operator and finished without repeating the uncertain mutation. The unchanged
native guard verifies only on a matching repeated intent. Consequently this
legitimate trajectory emitted zero SDK receipts. Its native TS/EOS were true;
these development grades are excluded from the official comparison.

The original readiness CLI unnecessarily coupled two different checks: a
successful autonomous native execution and activation of a conditional SDK
path. Searching more autonomous tasks until the model repeats a write would
neither strengthen source validation nor justify selecting favorable outcomes.
This amendment separates those checks before protocol publication:

1. Require the current-source, normal-return native clean baseline and guarded
   fault run, each with a complete passed independent replay audit. Require
   the guarded fault to trigger, but do not require its model to repeat a write.
2. Require the passed two-call tool roundtrip on the exact current local
   runtime, without any native task or service dispatch.
3. Separately validate the actual receipt path in a zero-inference fixture.
   Take the first saved public mutation proposal from the audited guarded
   development run. On fresh instances of that same excluded native world,
   apply that proposal twice through the original native guard and the actual
   installed SDK receipt integration. The second identical proposal is
   explicitly scripted for coverage. Require the native fault, at least one
   real SDK receipt, public-report reconstruction and exact native observation,
   intervention, wait, settled-world and effect parity.

The fixture performs no new model generation, inspects no target to choose an
action, supplies no native task score and counts as no autonomous trajectory.
It is path validation, not an improvement in task performance. It never injects
actions into the official matrix. Official runs may emit zero receipts when
the model does not request verification; their receipt coverage is an outcome.

A separate explicitly named readiness checker will bind all three proofs and
this amendment, while preserving the original stricter CLI and failed gate
conditions. The frozen protocol will bind the new readiness artifact. This is
a prospective change to readiness evidence, not a postcollection score change.
The existing development ceiling remains 24; the interrupted 11-call
reservation stays fully held. Six of eight task-independent completion calls
have been used; the fixture consumes none. No humans, paid inference or GitHub
Actions are introduced.
