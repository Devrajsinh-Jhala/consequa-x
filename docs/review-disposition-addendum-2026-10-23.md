## Required native metric and audit qualifications

The unchanged grader, rather than the README shorthand, determines each native
endpoint. `TS` requires target minimums and no graded collateral change;
`EOS = TS && dup_executed == 0`. `EOS` need not imply exact target counts or
zero extraneous writes. `exact_state` concerns target live counts only.
`clean_success` requires `TS` and zero live duplicates. Status targets have no
execution-matching branch, upsert execution counts are capped by final live
count and refund counts are not. `dup_compensated` is a derived difference,
not the number of compensation operations. These are domain-qualified native
metrics, not a universal physical exactly-once theorem.

An audited native error return can retain a real post-settlement grade. Native
grade availability, error-free execution and semantic task success therefore
have different denominators. Missing grades and missing usage remain
unavailable, while all planned slots stay in the primary operational
denominator. Assigned fault conditions define strata; actual fault triggering
does not decide which episodes are included.

The independent code audit replays the original native guard and recomputes
receipt/public-status bindings. It does not re-execute the SDK, independently
validate service source authority, or freshly reconstruct the live tokenizer.
Saved render/token proofs receive consistency checks. This distinction must
survive the abstract, methods, captions, artifact README and final conclusion.
